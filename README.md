# ระบบประสานงานลูกเสือช่วยเหลือ

เว็บแบบไม่ต้องเข้าสู่ระบบ แบ่งการทำงานเป็น 2 ระบบที่ใช้ฐานข้อมูล PostgreSQL เดียวกัน

## ระบบ 1 ทะเบียนกำลังและจัดชุดปฏิบัติการ

- เปิดรับลงทะเบียนกำลังและทรัพยากร 6 กลุ่มตามแบบฟอร์มที่ 1
- เก็บ ScoutDD ID เลขประจำตัวประชาชน หน่วยงาน เบอร์โทร พื้นที่ ทักษะ ยานพาหนะ อุปกรณ์ และช่วงเวลาที่พร้อม
- ศูนย์ส่วนกลางค้นหาทะเบียน เลือกหัวหน้าชุด และจัดสมาชิกตามแบบฟอร์มที่ 2
- รองรับชุดปฏิบัติการ 4 ประเภท ได้แก่ สิ่งของช่วยเหลือ ศูนย์พักพิง พื้นที่ปลอดภัยสำหรับเด็ก และฟื้นฟูสถานศึกษา

## ระบบ 2 รับคำร้องและประสานศูนย์ย่อย

- ประชาชนหรือหน่วยงานส่งคำร้องโดยไม่ต้อง Login
- ศูนย์ส่วนกลางตรวจสอบและมอบหมายคำร้องให้ศูนย์ย่อยตามพื้นที่
- ศูนย์ย่อยแต่ละแห่งใช้ลิงก์ลับเฉพาะของตนเองเพื่ออัปเดต 8 ขั้นตอนตามแบบฟอร์มที่ 3 ส่วนที่ 2
- Dashboard สาธารณะอัปเดตแบบ real time และไม่แสดงข้อมูลส่วนบุคคล

## การเข้าถึงโดยไม่ใช้หน้า Login

- หน้าลงทะเบียนและหน้าส่งคำร้องเป็นสาธารณะ
- ศูนย์ส่วนกลางใช้ลิงก์ที่มี token แบบสุ่มและเก็บเฉพาะค่า hash ในฐานข้อมูล
- ศูนย์ส่วนกลางสร้างศูนย์ย่อยและรับลิงก์ลับของศูนย์นั้นเพียงครั้งเดียว
- ตารางข้อมูลจริงเปิด RLS และไม่อนุญาตให้ anonymous อ่านโดยตรง

## ติดตั้งฐานข้อมูล

1. สำหรับฐานข้อมูลใหม่ ให้รัน `supabase/schema.sql`
2. รัน `supabase/migration-002-two-systems.sql`
3. สร้างลิงก์ศูนย์ส่วนกลางครั้งแรกจาก SQL Editor:

```sql
select public.provision_central_access('ศูนย์ส่วนกลาง');
```

4. นำ token ที่ได้ไปต่อท้าย URL รูปแบบ `#center/TOKEN`
5. เก็บลิงก์นี้เป็นความลับ เพราะผู้ที่มีลิงก์สามารถเห็นข้อมูลทะเบียนและจัดการระบบได้

## Deploy ด้วย GitHub Pages

Repository variables ที่ workflow ใช้:

- `SUPABASE_URL`
- `SUPABASE_PUBLISHABLE_KEY`

เมื่อ push เข้า branch `main` ระบบจะสร้าง `config.js` และ deploy หน้าเว็บอัตโนมัติ
